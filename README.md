# AI Agent Evaluation and Reliability Platform

A local platform for testing autonomous AI agents before deployment. It analyzes agent code and prompts, generates adversarial scenarios, runs evaluations through a controlled tool gateway, and produces reliability scorecards with failure analysis.

The project is split into a Python FastAPI backend and a React/Vite frontend.

## What It Provides

- Agent intake from local demonstration agents or submitted source files
- AST-based inspection of Python and TypeScript agent code
- Scenario generation across normal, edge, recovery, adversarial, safety, security, stress, and chaos cases
- Sandboxed tool execution with trace collection and fault injection
- Hybrid rule-based and Gemini-powered evaluation
- Safety versus capability scorecards and failure clustering
- Live attack testing with counterfactual replay
- Pipeline telemetry for evaluation stages
- Optional Supabase persistence with an in-memory fallback for local development

- Python 3.10 or newer
- pip
- Node.js 18 or newer and npm
- A Gemini API key for AI-powered analysis (optional; mock mode works without it)
- Supabase project credentials for persistent storage (optional)

## Configuration

Create `backend/.env` when needed:

```env
GEMINI_API_KEY=your_google_gemini_api_key_here
GEMINI_MODEL=gemini-3.6-flash
PORT=8000
ENVIRONMENT=development

# Optional persistent storage
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_KEY=your_service_role_key
```

Without `GEMINI_API_KEY`, the backend uses deterministic or template-based fallbacks. Without Supabase credentials, it uses in-memory storage and logs a warning at startup.

### Enable Supabase Persistence

The backend store writes registered agents, their normalized specifications, artifact hashes, uploaded source files, scenarios, evaluations, scorecards, failure clusters, and pipeline runs to Supabase. Uploaded agents now have first-class `agent_artifacts` and `agent_files` manifest records; the normalized specification remains derived data in `agents.agent_spec` for backward compatibility.

Run these SQL files in the Supabase SQL Editor, in order:

1. `backend/migrations/001_init_schema.sql` for a new project
2. `backend/migrations/002_store_compatibility.sql` for an existing project or after applying the first migration

After the migrations complete, restart the backend. The startup log should report `Supabase connected — persistent storage active.` New agents will then remain available after a browser refresh or backend restart. If the schema is not applied, the app intentionally falls back to in-memory data and new records will be lost when the process stops.

The frontend uses `VITE_API_URL` when set. The default API URL is `http://localhost:8000/api`.

## Run Locally

Open two PowerShell terminals from this directory.

### 1. Start the backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

The backend is available at:

- Health check: http://localhost:8000/
- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc

### 2. Start the frontend

```powershell
cd frontend
npm install
npm run dev
```

Open http://localhost:5173 in a browser.

The Vite development server listens on port `5173`. Set `VITE_API_URL` if the backend runs somewhere else, for example in `frontend/.env`:

```env
VITE_API_URL=http://localhost:8000/api
```

## API Areas

The backend mounts its REST API below `/api`:

- `/api/agents` - registered agent records
- `/api/intake` - inspect and register agents
- `/api/capabilities` - tool capability mappings
- `/api/scenarios` - strategies, scenario generation, and coverage
- `/api/evaluations` - evaluation jobs, scorecards, clusters, and regression comparisons
- `/api/live-attack` - adversarial execution and counterfactual analysis
- `/api/calibration` - judge calibration data
- `/api/pipeline` - execution telemetry

Interactive endpoint documentation is generated by FastAPI at `/docs`.

## Development Notes

- Backend data is temporary unless Supabase is configured.
- Keep API keys and service credentials in `.env` files; they are excluded by the repository `.gitignore`.
- The frontend currently uses local page state rather than a client-side router.
- The backend CORS policy is open for local development and should be restricted before production deployment.
